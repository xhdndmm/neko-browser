# 国际化（i18n）

GUI 支持多语言界面：英文（源语言）、简体中文、繁体中文、日文、韩文、
阿拉伯文、俄文。阿拉伯语会同时把整个应用布局切换为 RTL（从右到左）。

## 架构

```text
src/ui/*.cpp            tr("...") 源字符串（英文）
        │  tools/update_translations.sh（lupdate，人工翻译）
        ▼
src/ui/i18n/neko_XX.ts  翻译源文件（文本，仓库的唯一事实来源）
        │  lrelease
        ▼
src/ui/i18n/neko_XX.qm  编译目录（二进制，**同样提交**）
        │  CMake configure：lrelease 重编译，或（无 Qt Linguist 时）直接拷贝
        ▼
build/…/i18n/neko_XX.qm + translations.qrc（AUTORCC 嵌入 neko_ui 静态库）
        │  运行时 ":/i18n/neko_XX.qm"
        ▼
main.cpp → i18n::ApplyLanguage() → QTranslator + 布局方向
```

**为什么 .qm 也提交**：CI 的部分构建环境（Windows 的 aqtinstall
`qtbase` 包）不包含 Qt Linguist 工具。`src/ui/CMakeLists.txt` 在找不到
`Qt6::LinguistTools` 时直接使用仓库里提交的 `.qm`；有工具时则从 `.ts`
重新编译（两条路径均已验证：`-DCMAKE_DISABLE_FIND_PACKAGE_Qt6LinguistTools=ON`
走 fallback）。

**静态库资源陷阱**：`qrc_translations.cpp.o` 位于静态库 `neko_ui` 中，
链接器默认丢弃没有被引用的目标文件——资源不会注册。`i18n.cpp` 用
全局命名空间里的 `NekoUiInitTranslationResources()`（唯一能展开
`Q_INIT_RESOURCE` 的位置）强制拉入，`EnsureTranslationResources()` 是对外
的安全入口；`InstallTranslators`/`ApplyLanguage` 都会先调用它。

## 语言选择

- 偏好键：`language`（`preferences.txt`，见 `preferences_keys.h`）；
  空值 = 跟随系统 locale。
- 启动时 `main.cpp` 在**任何窗口创建之前**读取偏好并安装翻译器
  （`neko::ui::i18n::ApplyLanguage`），`neko_gui_screenshot` 走同一路径。
- 系统 locale 匹配规则（`ResolveLanguageId`）：精确匹配（`zh_TW`）；
  语言标签匹配（`ja_JP` → `ja`）；`*Hant*`、`zh_HK`、`zh_MO` → `zh_TW`；
  其余 `zh*` → `zh_CN`；无匹配 → 英文。
- 设置面板提供语言下拉（"跟随系统" + 各语言的原生名称）。**切换语言
  重启后生效**（状态栏提示）：翻译器在启动时安装，整个窗口的重译等同
  于重建 UI，不做运行中热切换。

## 更新翻译（开发者流程）

```bash
# 修改 UI 字符串后（tr("...")）：
tools/update_translations.sh     # lupdate 提取 + lrelease 编译
cmake -S . -B build/release      # 让 CMake 把新 .qm 放进构建目录
# 提交 src/ui/i18n/ 下的 .ts 与 .qm
```

- 需要 Qt Linguist（`lupdate6`/`lrelease6`，发行版包名通常是
  `qt6-tools` 或 `qttools`）。脚本可用 `LUPDATE`/`LRELEASE` 环境变量
  指向自定义路径。
- `.ts` 中 `type="unfinished"` 的条目**有意保持原文**：符号
  （`◀ ▶ ⟳ ⌂ − +`）、格式串（`100%`、`0/0`、`?`）、CSS 属性/值/关键字
  （`display`、`flex`、`line-height`、`(inherited)` 除外……）等技术
  术语属浏览器 DevTools 惯例，不翻译（`(inherited)`、面板标题等
  可翻译项已翻译）。
- 修改 `.ts` 后必须重新 configure（`.qm` 在 configure 阶段生成）；
  只改 C++ 代码不需重跑 lupdate。

**编辑器提示**：`.ts` 是 **XML 格式**的 Qt 翻译源（TS = *Translation
Source*，与 TypeScript 的 `.ts` 只是历史撞名）。Qt 官方扩展
（`theqtcompany.qt-core`，已列入 `.vscode/extensions.json` 推荐）注册了
专门的 `qt-ts` 语言（语法高亮、括号匹配），但**有意不占用 `.ts` 扩展名**
（避免与 TypeScript 冲突），因此仓库的 `.vscode/settings.json` 将
`*.ts` 关联为 `qt-ts`：安装该扩展后获得完整的翻译文件支持；未安装时
按纯文本显示（不会退回 TypeScript 误解析）。也可用 Qt Linguist
（`linguist6`）以图形界面审校翻译，或直接编辑 XML。

## 运行时细节

- 同时装载 `qtbase_<语言>.qm`（Qt 安装目录内），使 `QMessageBox`
  等标准对话框也本地化；Qt 未安装对应目录时静默跳过（标准对话框
  保持英文，属可接受降级）。
- 阿拉伯语：`QApplication::setLayoutDirection(Qt::RightToLeft)`，
  工具栏、dock、对话框全部镜像；多语言混排文本（如 `%1 — %2`）
  由 Qt 按段落方向处理。
- 翻译查找作用于全部 `tr()` 字符串；`QStringLiteral` 硬编码的
  符号与格式化片段（如 `"+"`、`"\u2026"`）不参与翻译，属预期。

## 已知限制

- 语言切换重启生效（无运行中热切换）。
- 未翻译字符串以英文显示（fallback），不会出现空文本。
- Qt 标准对话框的本地化依赖构建机安装的 Qt 翻译目录。
- 平台原生对话框（系统文件选择器等）由系统语言决定，不随应用语言。
