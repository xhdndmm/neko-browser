# 架构决策记录 0006：GUI 使用 Qt6（Widgets）

- 状态：**Accepted**（2026-08）
- 决策者：架构组 + 用户

## 背景

Phase 7 需要交付真实浏览器 UI（标签页、地址栏、工具栏、DevTools、侧边面板）。
候选方案：

1. **自研窗口/事件/控件栈**（X11/Wayland/Win32/Cocoa 直接抽象）
   —— 工作量巨大，会拖慢后续引擎里程碑；与"不跳步"原则冲突。
2. **Qt6 Widgets**
   —— 成熟的跨平台 UI 基础设施（X11/Wayland/Windows/macOS），C++ 原生，
      无语言绑定层，社区与 CI 支持好，许可（LGPL）可接受。
3. **其他（GTK/FLTK/WebView 等）**
   —— GTK 更偏 GNOME 且 C 接口；FLTK 过简；WebView 属于"外包浏览器 UI"，禁止。

Qt 是**基础设施**（等同网络库/字体库），不是浏览器引擎的替代品：
引擎（HTML/CSS/布局/绘制/网络/存储）仍全部为自研，Qt 只提供窗口、
事件循环、控件、QImage 宿主。

## 决策

- GUI 采用 **Qt6 Widgets**（`NEKO_BUILD_UI=ON` 时构建，默认开启）。
- 依赖 `Qt6::Widgets`，开启 `AUTOMOC`；CI/无头环境用
  `QT_QPA_PLATFORM=offscreen` 平台做冒烟测试与截图。
- UI 与引擎通过 `browser::BrowserController` 解耦：
  `ui → browser → engine`，UI 不得直接触碰引擎内部。
- 跨线程：`BrowserWorker` 在专用线程持有 `BrowserController`，
  经队列 + 条件变量通信，`StateChanged` 信号（QueuedConnection）
  驱动 UI 刷新；`WebView` 每次绘制按 `tab_id` 解析控制器标签，
  避免 `CloseTab` 后指针悬垂。

## 后果

- 优点：跨平台窗口/控件/事件/图像宿主一次到位；offscreen 平台使
  GUI 可无头测试与截图；开发速度大幅提升。
- 缺点：引入 Qt 构建依赖（Qt6 base 需用户安装）；AUTOMOC 增加构建
  复杂度；Qt 许可为 LGPL（动态链接，未修改 Qt 源码，合规）。
- 备选（若 Qt 不可用）：`NEKO_BUILD_UI=OFF` 保留纯 headless CLI，
  引擎侧零 Qt 依赖。
